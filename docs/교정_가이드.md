# 📱 OCR 교정 가이드 (맥북 M1 기준)

> 책을 OCR 한 뒤 **틀린 글자·단어를 보수적으로 고치고**, 교정본으로 **책 PDF 를 다시 만드는** 방법입니다.
> 원칙: **근거가 있는 수정만 자동 적용**, 나머지는 **보류 → 검수 리포트**. 원본은 절대 덮어쓰지 않습니다.

---

## 0. 한눈에

```
OCR 결과(work/pages)
  → ① 표기 정규화 (결정적, 되돌리기 가능)
  → ② 의심 구간 탐지 (고치지 않음)
  → ③ 후보 만들기 (책 어휘 + 자모 편집거리)
  → ④ Gemini 가 수정 목록 제안 (엄격 검증, 과교정은 자동 거절)
  → ⑤ 쪽 이미지에서 줄을 잘라 Gemini 가 독립적으로 다시 읽기
  → ⑥ 판정: 자동 수정 / 보류 / 오탐
  → 리포트(report.html) → 검수 → corrected/ → 책 PDF
```

**자동 수정이 되려면** 독립 근거가 둘 이상 맞아야 합니다.
- 이미지 검증 ON: 이미지 재판독이 후보와 일치(원문과는 불일치)
- 이미지 검증 OFF(`--no-verify`): LLM 제안이 책 어휘 후보 또는 두 번째 OCR 과 일치 (숫자·영문은 두 번째 OCR 일치 필요)
- 띄어쓰기만 바꾸는 제안(글자 불변)은 예외적으로 채택
- 그 밖에는 전부 **보류** (이미지가 원문과 같으면 **오탐**으로 두고 고치지 않음)

## 1. 맥북 실행 순서

### 1-1. 준비 (한 번만)
```bash
cd booktest
source .venv/bin/activate
git fetch && git checkout claude/proofread-pipeline
pip install -r requirements.txt
brew install tesseract tesseract-lang   # tesseract 쪽 단어 신뢰도(tsv)를 쓰려면. 없어도 동작
```
`.env` 확인 (**모델 이름 꼭 확인**):
```
GEMINI_API_KEY=발급받은키
GEMINI_MODEL=gemini-3.5-flash-lite
GEMINI_RPM=10
```
⚠️ `.env.example` 을 그대로 복사했다면 `GEMINI_MODEL=gemini-2.5-flash` 일 수 있습니다. 실행 첫 줄에 `Gemini 모델 …` 이 찍히니 맞는지 보세요.
(`gemini-3.5-flash-lite` 이름은 이 개발 환경에서 실제 존재 여부를 **확인하지 못했습니다**. 404/모델 오류가 나면 공식 문서에서 현재 무료 모델명으로 바꾸세요.)

### 1-2. 키 없이 먼저 점검 (무료·무호출)
```bash
python -m bookpdf proofread output_tess/work --no-llm --no-verify --pages 1-10
```
- `output_tess/work` 는 기존 실행의 `--out output_tess` 의 work 폴더입니다(`pages/pNNNN.json` 이 있는 곳).
- 결과: `output_tess/work/proofread/report.html` (아이폰에서는 파일 앱 → 열기)
- 이 모드는 **탐지·후보·리포트만** 만들고 자동 수정은 거의 없습니다.

### 1-3. 소량 Gemini 시험 (10쪽, 호출 상한)
```bash
python -m bookpdf proofread output_tess/work --pages 1-10 --max-calls 40
```
- 의심 구간의 **앞뒤 문맥과 쪽 이미지 조각이 Gemini 로 전송**됩니다(시작할 때 안내문이 나옵니다).
- 한도(429)에 걸리면 저장하고 멈춥니다. **같은 명령을 다시 실행**하면 받은 응답은 재사용하고 이어서 합니다.

### 1-4. 리포트 확인 → 적용
```bash
python -m bookpdf proofread output_tess/work --pages 1-10 --apply
```
- `output_tess/work/corrected/` 에 교정본(pNNNN.md/json), `corrections_log.json`(수정 로그) 생성
- 원본 `work/pages` 는 그대로
- 마음에 안 들면 되돌리기: `--revert` → `work/restored/` 에 원문 복원

### 1-5. 보류 항목 검수
`output_tess/work/proofread/held_review.txt` 를 열어 `H001 =` 뒤에 답을 적습니다 (아이폰 메모 앱 가능).

| 적는 값 | 뜻 |
|---|---|
| `1` `2` `3` | 그 번호 후보로 고침 |
| `x` | 원문 유지 |
| `t:글자` | 직접 입력 (숫자만 쓸 때도 `t:2022`) |
| (빈칸) | 보류 유지 |

```bash
python -m bookpdf proofread output_tess/work --pages 1-10 --review output_tess/work/proofread/held_review.txt
```
API 호출 없이 반영됩니다. 지난 실행 이후 원본이 바뀌었으면 거부합니다.

### 1-6. 전체 책으로 확대
```bash
python -m bookpdf proofread output_tess/work --alt-work output_gemini/work --apply
```
- `--alt-work`: **두 번째 OCR**(예: tesseract 본 + gemini 본) 폴더. 단어가 서로 다른 곳을 의심 신호로 씁니다 → 정확도에 도움이 될 것으로 **추정**(실제 책 미검증).
- 하루 한도를 넘으면 멈추고 다음 날 같은 명령으로 이어집니다.

### 1-7. 교정본으로 책 PDF
```bash
python -m bookpdf proofread output_tess/work --pdf --embed-page-images --pdf-out output_proofread --title "책 제목"
```
- 원래 실행에서 쓴 `--embed-page-images`, `--heading-ratio` 등은 **같게** 주세요.
- 한자는 Noto Sans CJK KR, 원문자(①㉠)는 (1)·(가) 로 자동 대체됩니다(기존 기능 그대로).
- `corrected/전체원문_교정.md` 도 함께 만들어집니다. 이 Markdown 만 따로 조판하려면 `--from-md 파일.md`.

## 2. 정답 쪽 10장 만드는 법 (정확도 측정용)

1. 서로 다른 유형을 섞어 **10쪽** 고르기: 본문 위주 5, 표·숫자 2, 영문 약어(MACD 등) 2, 신뢰도 낮은 쪽 1
2. 복사: `cp work/pages/p0034.md gold/p0034.md` (쪽마다)
3. 원본 이미지 `work/page_images/p0034.png` 를 보며 **틀린 글자만** 고치기
   - 맞춤법·문체 교정 ❌, **책에 인쇄된 그대로**
   - 줄 구조(줄바꿈, 표의 `|`)는 바꾸지 않기
4. `gold/` 폴더는 **커밋 금지**(`.gitignore` 처리됨)
5. 측정:
```bash
python -m bookpdf proofread output_tess/work --pages 34,40-42 --apply --evaluate gold --audit 20
```
- CER/WER 의 **수정 전 → 정규화만 → 수정 후**가 출력됩니다. 10쪽 결과는 **참고용**(책 전체 정확도의 증거 아님).
- `--audit 20`: 채택된 수정 중 무작위 20건 검수표(`proofread/audit.md`). `audit_answers.txt` 에 `A001 = o`(맞게 고침) / `x`(잘못 고침) / `?` 를 적고:
```bash
python -m bookpdf proofread output_tess/work --audit-score output_tess/work/proofread/audit_answers.txt
```
→ **잘못 고친 비율**과 95% 구간이 나옵니다.

### 결과로 붙여 줄 숫자 (본문 말고 통계만)
```bash
python -c "import json;print(json.load(open('output_tess/work/proofread/stats.json')))"
python -c "import json;print(json.load(open('output_tess/work/proofread/evaluate.json'))['summary'])"
```
- 위 두 줄은 **개수·비율만** 나옵니다(책 문장 없음). `evaluate.json` 전체나 리포트는 본문이 들어 있으니 붙이지 마세요.

## 3. 임계값 조정법

> 기본값은 **합성 데이터 기준**이며 실제 책으로는 **미검증**입니다. 10쪽 시험 후 조정하세요.

| 옵션 | 기본 | 올리면 | 내리면 |
|---|---|---|---|
| `--min-score` | 0.30 | 의심 구간↓ (놓침↑) | 의심 구간↑ (비용·보류↑) |
| `--conf-thr` | 60 | tesseract 낮은 신뢰 단어 더 많이 의심 | 덜 의심 |
| `--rare-max` | 1 | 2 면 두 번 나온 같은 오타도 '드문 낱말' | 1 이 가장 보수적 |
| `--min-confidence` | 0.7 | LLM 이 확신해도 보류↑ (안전) | 자동 수정↑ (위험) |
| `--max-char-dist` | 3 | 큰 변경 허용 (위험) | 작은 변경만 |
| `--max-jamo-dist` | 4 | 〃 | 〃 |
| `--batch-lines` | 8 | 요청 수↓ (프롬프트↑) | 요청 수↑ |
| `--year-range` | 1900-2035 | 책 연도 범위에 맞추기 | |

**조정 순서 추천**: ① `잘못 고친 비율`이 높으면 → `--min-confidence 0.85`, `--max-char-dist 2`, `--no-verify` 쓰지 않기 ② 보류가 너무 많고 내용은 맞으면 → 이미지 검증 ON 유지 + `--alt-work` 추가 ③ 놓치는 오류가 많으면 → `--min-score 0.2`.

용어집: `work/glossary.txt` (한 줄에 용어 하나)에 책의 고유명사·전문용어를 넣으면 **보호**됩니다. 자동 수집본 `proofread/glossary_auto.txt` 는 **같은 오타가 반복돼 섞였을 수 있으니** 틀린 항목은 지우세요. 영문 약어는 `--acronyms 파일` 로 추가.

## 4. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| `GEMINI_API_KEY 가 없습니다` | `.env` 없음 | `.env` 확인, 또는 `--no-llm --no-verify` |
| 모델 404 / not found | 모델명 | `.env` 의 `GEMINI_MODEL` 을 현재 무료 모델로 |
| `일일 한도(RPD) 도달` 후 멈춤 | 무료 한도 | 다음 날 **같은 명령** (응답 캐시 재사용). `--max-calls N` 으로 미리 제한 |
| `분당 한도(RPM)` 반복 | 호출이 빠름 | `.env` 의 `GEMINI_RPM` 낮추기 |
| 자동 수정이 0건 | 근거 부족이 정상 동작 | 이미지 검증 ON 확인, `--alt-work` 추가, 리포트의 보류 이유 보기 |
| 보류가 너무 많음 | 후보/근거 부족 | 용어집 보강, `--min-score` 올리기, `held_review.txt` 로 검수 |
| 잘못 고쳐짐 | 임계값 느슨 | `--revert` 후 3장 표대로 조정. 수정 로그: `corrected/corrections_log.json` |
| `거절된 LLM 제안`이 많음 | 모델이 과교정 시도 | 정상(안전 검사가 막은 것). 사유별 건수는 리포트 상단 |
| 한글 사이에 공백이 많음 (`이 동 평 균`) | tesseract 의 알려진 한계 | LLM 이 띄어쓰기를 고치면(글자 불변) 자동 채택. 가능하면 Gemini 본 OCR 을 `--alt-work` 로 |
| tesseract 없음/느림 | 미설치 | `brew install tesseract tesseract-lang`, 또는 `--no-tsv` |
| `--review` 가 거부됨 | 원본이 바뀜 | 다시 `--review` 없이 실행해 decisions 새로 생성 |
| PDF 에 `□` | 두 글꼴에 없는 글자 | 리포트(원래 실행의 `리포트.md`) '글꼴에 없는 글자' 확인 |
| 회사/학교 PC 에서 막힘 | 네트워크 정책 | **우회하지 말고** 막힌 요청 문구를 그대로 알려 주세요 |
| 책 본문이 외부로? | Gemini 호출 시 전송 | 의심 구간 문맥+이미지 조각만 전송. 싫으면 `--no-llm --no-verify` |

## 6. 확인된 것 / 미검증

- ✅ 합성 한국어 샘플 + 가짜 Gemini 로 전 단계 테스트 통과 (정규화·탐지·후보·과교정 거절·이미지 검증·적용/되돌리기·검수 반영·CER/WER·PDF)
- ✅ 실제 tesseract(kor) 로 tsv 단어 신뢰도·단어 상자 경로 동작 확인 (합성 이미지)
- ✅ 한자(兵赤黑)는 Noto 글꼴, 원문자(①㉠)는 (1)·(가) 대체 — 교정본 PDF 에서 확인
- ❌ **실제 Gemini 호출은 미검증** (이 환경에 키 없음). 모델명 `gemini-3.5-flash-lite` 존재 여부도 미확인
- ❌ **실제 책에서의 정확도(CER/WER 개선폭, 잘못 고친 비율)는 미검증** — 위 2번 절차로 맥북에서 측정
- ❌ 임계값 기본값, 자모 혼동 쌍 목록(경험적)은 실제 책 미검증
- ❌ 실제 책 스캔의 tesseract 단어 상자 정렬(합성 이미지에서는 정렬 일부 불안정 관찰)
- ⚠️ 바른(Bareun) 등 외부 맞춤법 API 는 **구현하지 않았습니다**(책 본문 외부 전송 기능 기본 꺼짐 원칙)
